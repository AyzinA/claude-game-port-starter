# 12 — Definition of done and fidelity levels

## Feasibility done

Input identity/path verified, substantive research, platform/middleware restrictions, asset/script path assessed, mod categories classified, report with decision and unknowns. Absence of evidence cannot be treated as GO.

## Parser done

Read-only; malformed input protections; sample original resource tested; format version validated; engine-neutral result; tests with synthetic fixtures and local real file; no copyrighted payloads in repo.

## Gameplay done

Script/native ownership understood; equivalent inputs, timing, state transitions, animation/sound effects, interruptions, save/load and game-version behavior verified. If merely approximate, document clearly.

## Mod support done

Mod format/version detected; compatible assets/data mounted safely; explicit precedence; conflicts; disable/uninstall; save fingerprint; rejection of unsupported executable mods; no changes to base files.

## Full-game claim done

Only after original-start-to-end scenarios across required branches/modes, all relevant mechanics and regression tests, installed data and performance constraints are verified. 1:1 behavior is a **target, never an unqualified marketing claim**.

## Confidence legend

`verified (original-run)`, `verified (resource/script)`, `implemented unverified`, `inferred`, `unsupported`, `blocked`.
